Away from your desk

Continue the conversation.
Not a new explanation.

Securely open the same Pi Cloud service from your phone or tablet. Find the session you were using and pick up the thread.

  • Follow up lightly: read a response, clarify a requirement, or add the next question. Leave detailed code review for a larger screen.
  • Keep the workspace running: the agent and repository stay on the machine hosting Pi Cloud, not on the phone.
  • Connect safely: remote access needs your own HTTPS and authentication setup. Don't expose the service just to try the mobile view.

Self-hosted by design

Your machine does the work.

Run Pi Cloud on a workstation or server you control. Connect your browser through your own network and secure remote-access setup.

⌘

Browser

Desktop, tablet, or phone. No local agent installation required on the device you browse from.

↔
⚙

Pi Cloud + Pi agent

Persistent sessions, terminals, tasks, memory, and repository tools on your workspace machine.

↔
◈

Your model provider

Use configured cloud APIs or local models. Data sent to a model follows your provider and tool configuration.

Self-hosting is not an agent sandbox. Review tool permissions and use HTTPS and appropriate authentication for remote access.

Start with Node.js 22+

Give your agent a place to work.

Install Pi Cloud, save the generated first-run password, and open http://127.0.0.1:3000. Configure model credentials in the agent profile dialog.

npm install -g pi-cloud && pi-cloud

Using an OAuth subscription? Sign in through the standalone Pi CLI as the same OS user first; WebUI OAuth sign-in is not yet available.
